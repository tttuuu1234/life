ノンス

2026年10月18日

ノンス（nonce、number used once）は、暗号化のたびに新しく用意する「1回だけ使う値」である。AES-GCM や ChaCha20-Poly1305 のように、同じ共通鍵で何度も暗号化する方式で必ず使う。秘密にする必要はなく、暗号文と一緒に保存・送信する。条件はただ1つ、同じ鍵で同じノンスを二度と使わないことである。

目隠しシートとしての仕組み

AES-GCM は、共通鍵とノンスから、ランダムに見える数列（キーストリーム）を作り、メッセージに重ねて（XORして）暗号文にする。この数列は、メッセージに重ねる目隠しシートと考えると分かりやすい。ノンスが変わればシートもまったく別物になるため、同じ文を送っても毎回違う暗号文になる。

使い回すと起きること

同じ鍵で同じノンスを使うと、同じ目隠しシート S が2回使われる。すると2つの暗号文を重ね合わせるだけでシートが打ち消し合って消え、メッセージ同士の関係がそのまま出てくる。

C1 = M1 ⊕ S        （1通目）
C2 = M2 ⊕ S        （2通目、同じノンス → 同じ S）
C1 ⊕ C2 = M1 ⊕ M2  （S が消える）

さらに片方の本文が推測できると（「おはよう」のような決まり文句）、C2 ⊕ M2 でシート S そのものが割り出され、もう片方の暗号文も読めてしまう。共通鍵は盗まれていないのに中身が漏れる点が重要である。

被害は読まれることにとどまらない。AES-GCM は改ざん検知用のタグを、鍵から作った秘密の値 H を使って計算する。同じノンスの暗号文が2つそろうと、H を含む式が2本手に入り、H を逆算できてしまう。H が分かれば、書き換えた暗号文にも正しいタグを付けられ、受信側は偽物に気づけない。

正しい使い方

  • 暗号化のたびに、96ビット（12バイト）の乱数をノンスとして作る。多くのライブラリは指定しなければ自動で作る。
  • 決して重複しないカウンター（1, 2, 3…）でもよいが、再インストールや複数端末で値が巻き戻らないよう管理が必要になる。
  • 乱数のノンスでも偶然の一致はありうるため、1つの鍵で暗号化する回数には上限がある（NIST の目安は約40億回）。それを超える前に鍵を替える。

ほかの「1回だけの値」との違い

名前使う場所目的
暗号化のノンスAES-GCM など暗号文を毎回バラバラにし、シートの重複を防ぐ
OIDC の nonceIDトークン古いIDトークンの使い回し（リプレイ）を防ぐ
チャレンジパスキーのログイン古い署名の使い回し（リプレイ）を防ぐ

どれも「毎回新しい値にして、前回のものと区別する」発想は共通だが、暗号化のノンスは重複すると暗号そのものが壊れる点で、扱いが最も厳しい。
