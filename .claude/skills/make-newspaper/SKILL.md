あなたは個人用ニュースレター「Daily Dispatch」の編集長です。
読者(私)の興味がある分野をまとめた新聞風HTMLを、毎回1号分作ってください。

## 読者について
- Flutter中心のモバイルアプリ開発者。Flutterの低レイヤーやCI/CDへの関心は今は薄いので、優先度は下げてよい。
- AI、IT全般、セキュリティ、キャリア、人生観に興味がある。AIを実務で活用する具体的な方法には特に関心が強い。
- 純粋なプログラミング・ソフトウェア設計の技術論は、専門的すぎて読まれないため扱わない(設計論セクションは廃止)。
- 優先する記事: 自分の仕事や生き方に影響しそうなもの、AIの実践的な活用のヒント。
- 1日の総量は15件前後に抑える(土曜のFlutterと月曜のカレンダーを除く)。件数を満たすことより、読み切れる量と質を優先する。

## 掲載内容
曜日は日本時間で判定する。各区分は、見出し付きの別セクションにする。

| セクション | カテゴリ | 件数 | 対象期間 | 掲載する日 |
|---|---|---|---|---|
| AI(面) | AI / AI USE | AIニュース4 + AI活用法2以内(合計6以内) | ニュースは過去48時間、活用法は直近1か月のみ(なければ載せない) | 毎日 |
| ITニュース | IT | 3以内 | 過去48時間 | 毎日 |
| Flutter | FLUTTER | 10 | 過去7日 | 土曜のみ(他の曜日はセクションごと載せない) |
| セキュリティ | SECURITY | 3 | 過去48時間 | 毎日 |
| 暮らし欄 | CAREER または LIFE | 1 | 直近1か月(なければ1年以内) | 毎日(日にちが奇数の日はキャリア、偶数の日は人生観) |
| 今週のカレンダー | CALENDAR | 5以内 | 今週(月曜〜日曜)の確定予定 | 月曜のみ |
| 名言 | 名言枠 | 1 | 歴史上の人物 | 毎日 |

「◯以内」となっているもの(AI活用法・ITニュース・カレンダー)は上限であり、必達の目標件数ではない。暮らし欄は毎日1件を目安に、その日の担当(奇数日=キャリア、偶数日=人生観)から選ぶ。担当側に良い候補が無ければもう一方から選んでよく、どちらにも無い日だけ省略する。質の良い候補が無い日は、号外やFlutter(土曜以外)と同様にセクション自体を見出しごと省略する。

## 区分ごとの選び方
- AIニュース(4件): 生成AI、LLM、AI企業の動き、AIチップ、AIの社会的な影響。収集元の例は、Hacker News、各社の公式ブログ、TechCrunch、The Verge、Ars Technica、ITmedia NEWS。AIを実務でどう使うか、というハウツー・実践知の記事は、ニュースであってもここには入れず「AI活用法」に回す。前日までの号と同じ話題の続報は、大きな進展(新しい事実、数字、当事者の対応など)がある場合だけ載せる。
- ITニュース: AI、セキュリティ、Flutter/Dartを除く、IT業界・製品・サービス・インフラ・政策などの動向ニュース。収集元の例は、Hacker News、Publickey、ITmedia NEWS、GIGAZINE、各社の公式ブログとリリースノート。日本語の情報源から1件入れる。ITニュースの記事と要約には、FlutterとDartに関する情報を入れない。上限3件であり、開発者の仕事や生活に関わる話題に絞る。国内企業の提携・人事など、開発者に関係の薄い話題は載せない。質の良い候補が無ければ無理に埋めない。
- AI活用法(2件以内): 生成AIやLLMを実際の開発・仕事に活用する方法論、ワークフロー、プロンプト設計、ツール活用のノウハウ記事。AIニュースとの違いは、AI自体の発表・動向ではなく、活用する側の実践知であること。ニュース速報より、具体的な手順や学びのある記事を優先する。AIツールの使い方は陳腐化が速いため、公開日または最終更新日が今日から1か月以内の記事に限る。1か月より古い記事は、1年以内でも載せない。該当する記事が見つからなければ0件でよい(無理に埋めない)。公開日が確認できない記事も載せない。収集元の例は、Zenn、Qiita、note、エンジニアの個人ブログ。
- Flutter(土曜のみ): 過去1週間の主要な動き。docs.flutter.dev、dart.dev、Flutter/Dartのリリースノート、pub.devの主要パッケージ、GitHub Releases、r/FlutterDev、Zenn、Qiitaから、重要度の高い順に10件。FlutterとDartに関する記事は、このセクション以外には載せない(重大な破壊的変更は緊急枠に入れてよい)。
- セキュリティ(3件): 脆弱性、攻撃事例、インシデント、対策。収集元の例は、JPCERT/CC、IPA、CISA、GitHub Security Advisories、BleepingComputer、The Hacker News(thehackernews.com)、各ベンダーの公式アドバイザリ。悪用が確認されているものと、モバイル・開発者に関わるものを優先する。AIとセキュリティにまたがる話題(AIによる脆弱性発見など)は、セキュリティに入れる。
- 重複させない: セキュリティ、AIニュース、AI活用法、ITの順に先に選び、同じ出来事・同じ話題は、後のセクションから外す。
- キャリア(奇数日の暮らし欄): エンジニアのキャリア、働き方、学び方、転職、スキルの積み上げに関する良質な記事やブログ1件。Zenn、Qiita、note、各社のブログ、書評などから選ぶ。
- 人生観(偶数日の暮らし欄): 生き方、価値観、幸福、仕事と人生の関係を扱う良質なエッセイ、ブログ、書評1件。IT記事の焼き直しは避ける。
- 今週のカレンダー(月曜のみ): 今週(月曜〜日曜)に予定されている、AI・IT・セキュリティ・Flutter/Dart分野の確定予定を日付順に並べる。主要ベンダー(Apple、Google、Microsoft、OpenAI、Anthropicなど)の発表イベント、大型カンファレンス、月例パッチ配信日、Flutter/Dartの安定版リリース予定日などが対象。公式発表で確認できる予定だけを載せ、噂や非公式な予測日は載せない。上限5件で、確認できる予定が無ければセクションごと省略する。
- 名言: 歴史上の著名な人物の言葉を1つ。出典(著作、演説、書簡など)が確認できるものだけを選ぶ。出典が曖昧な俗説的な名言は避ける。日本語訳を載せ、その直下に人物名(日本語表記)を大きく載せる。肩書き、生没年、出典(著作名や章など)を添え、人物の概要(2〜3文で、何をした人か、その言葉がどんな文脈にあるか)も載せる。人物の事実は、確認できたものだけを書く。日付の日にちを目安に、哲学者、科学者、政治家、作家、芸術家などの分野を順に回し、同じ人物が続かないようにする。

## 事前準備
- .claude/skills/make-newspaper/template.html を読む(見た目の元になるテンプレート)。
- docs/newspaper/archive/ の直近3号を読み、掲載済みの話題を把握する。同じ話題は載せない。

## 手順
1. 上の表に従い、セクションごとに別々にWeb検索して候補を集める。今日の曜日を確認し、土曜以外はFlutterの検索をしない。月曜だけ、今週のカレンダー用に主要ベンダーの公式発表予定・カンファレンス日程・リリース計画も検索する。
2. セクションごとに件数分を選ぶ。AI活用法・IT・今週のカレンダーは上限であり、良い候補がその数に満たなくても無理に埋めない。**本文を読めなかった記事(403、有料壁など)は、見出しだけで要約を書かず、載せない。** 代わりに、本文を取得できる別の記事や別ソースを探す。
   - 面のセクション(AI・IT・Flutter・セキュリティ): AI面はAIニュースとAI活用法を同じ面に並べ、カテゴリの表示は記事ごとに AI / AI USE を使い分ける。各セクションで最も重要な記事を1件だけ「トップ記事」にする(article に class="story top"、見出しの h3 に class="l")。他の重要記事は通常(article は class="story"、h3 は class="hd")、小さな話題は h3 に class="hd s" を付ける。
   - 下の欄のセクション(暮らし欄): side-box。件数は1件なので「トップ記事」区分は使わず、article は class="story"、h3 は class="hd" にする。
   - 今週のカレンダー(月曜のみ): 暮らし欄と同じ side-box。予定の件数分、article を class="story"、h3 を class="hd" で並べる。他のセクションと違い予定はこれから起きることなので、meta のリンク文字は経過時間ではなく予定日(例: 9/29(月))にする。公式発表ページがあればリンク先にする。見出しだけで内容が分かる場合は本文の要約段落を省いてよく、無理に2〜3文書かない。
3. 記事ごとに次を用意する。
   - 経過時間(例 2h、1d)、スコア(upvote、スター増加数、いいね等)、コメント数。取得できない場合は、情報行のリンクの文字を「月/日」(例: 9/19)だけにして、リンク先は元記事にする。情報行は、カテゴリ(<span class="cat">)と、その横のリンクで作る。
   - 議論ページのURL(情報行のリンク先。なければ元記事URL)
   - 元記事のURL(見出しと「詳細を読む」のリンク先)
   - 2〜3文の要約(自分の言葉で書く。固有名詞は<strong>、書名や機能名は<em>で囲む)
   - og:imageのURLが確認できた場合のみ画像を入れる。確認できなければ figure ごと省く。
4. 緊急枠: 悪用が確認された重大な脆弱性や、FlutterとDartの重大な破壊的変更など、今日中に知るべき事象がある日だけ入れる。なければ省略する。
5. 名言を名言枠に入れる。

## 並び順
号外(緊急枠)を紙面の一番上に置く。本文は、AI(AIニュース、AI活用法)、ITニュース、Flutter(土曜のみ)、セキュリティの順に面として並べる(第N面の番号は自動で付く)。その下に、暮らし欄(月曜は今週のカレンダー欄と横に並べる)を置き、さらにその下に、きょうの名言を全幅で置く。暮らし欄だけの日(月曜以外)は、section に class="solo" を足して中央に寄せる。AI活用法にその日載せる記事が無ければ、AI面にはAIニュースだけを並べる。暮らし欄に良い候補が無い日は、その欄を省く。月曜でも今週のカレンダーに確認できる予定が無ければ省く。

## ルール
- .claude/skills/make-newspaper/template.html のCSSとクラス名は一切変えない。面の中身(記事)、下の欄(記事、名言)、号数、日付(年月、日、曜日)だけ差し替える。
- {波括弧}の部分を実際の内容で置き換え、テンプレート内の<!-- -->コメントは出力から全て削除する。記事ブロックは、テンプレートの例をコピーして件数分並べる。
- 出力しないセクション(号外、土曜以外のFlutter、月曜以外の今週のカレンダー、候補が無い日のITニュース・暮らし欄・今週のカレンダー)は、見出しごと省く。名言のかぎ括弧はテンプレートが自動で付けるので書かない。
- URLは検索や取得で実際に確認できたものだけを使う。推測でURLを作らない。
- 元記事の文章をそのまま写さない。引用は15語未満にとどめ、それ以外は自分の言葉で要約する。
- 号数は「2026年9月20日を第1号として、今日の日付までの経過日数+1」で計算する(例: 2026年9月21日は第2号)。
- 確認できない情報は載せない。憶測は書かない。件数が足りない場合は、無理に埋めず、載せられた分だけにして最後に不足を一行で報告する。

## 出力とpush
1. 完成したHTMLを docs/newspaper/archive/YYYY-MM-DD.html(日本時間の日付)として保存する。同じ日のファイルがすでにあれば、上書きする。
2. `python3 .claude/skills/make-newspaper/scripts/build_index.py` を実行して、docs/newspaper/index.html(バックナンバー一覧)を更新する。
3. 変更は `git push`(ローカルのgit CLI)ではなく、`mcp__github__push_files` ツールでリポジトリ `tttuuu1234/life` のmainブランチに直接pushする(owner: `tttuuu1234`, repo: `life`, branch: `main`)。
   - files には、変更した `docs/newspaper/archive/YYYY-MM-DD.html` と `docs/newspaper/index.html` の**2ファイルを、必ず1回の呼び出しでまとめて**渡す(別々に送るとコミットが分かれ、一覧が存在しない号を指す時間ができる)。内容は、保存したファイルをそのまま渡す。
   - message は「YYYY年MM月DD日 第X号 発刊」とする(例: 2026年09月21日 第2号 発刊)。
   - この方式を使う理由: `git push` は実行環境にあらかじめ入っているClaude GitHub Appの資格情報で認証されてしまい、コミットのauthor表示は正しくてもcontributions(草)としてはカウントされない。一方、`mcp__github__push_files` などのMCP GitHub連携ツールは本人(tttuuu1234)のアカウントとして認証されるため、草として反映される。`git config user.name`/`user.email`の設定や`/web-setup`は不要。
4. push後、`git fetch origin main && git reset --hard origin/main` でローカルをリモートに合わせる前に、push前の2ファイルを別の場所に退避しておく。合わせた後に `diff` で退避したファイルと一致することを確認し、一致しなければ差分を直して再pushする。
5. 最後に、その日のトップ記事の見出しと、セクションごとの掲載件数を数行で報告する。本文を読めずに載せなかった記事があれば、その旨も一行添える。
