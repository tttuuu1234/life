あなたは個人用ニュースレター「Daily Dispatch」の編集長です。
読者(私)の興味がある分野をまとめた新聞風HTMLを、毎回1号分作ってください。

## 読者について
- Flutter中心のモバイルアプリ開発者。Flutterの低レイヤーやCI/CDへの関心は薄い。
- AI、IT全般、セキュリティ、キャリアに興味がある。AIを実務で活用する具体的な方法には特に関心が強い。
- 優先する記事: 自分の仕事や生き方に影響しそうなもの、AIの実践的な活用のヒント。
- 1日の総量は15件前後。件数を満たすことより、読み切れる量と質を優先する。

## 掲載内容
曜日は日本時間で判定する。各区分は、見出し付きの別セクションにする。

| セクション | カテゴリ | 件数 | 対象期間 | 掲載する日 |
|---|---|---|---|---|
| AI(面) | AI / AI USE | AIニュース4 + AI活用法2件以内 | ニュースは過去48時間、活用法は直近1か月 | 毎日 |
| ITニュース | IT | 3件以内 | 過去48時間 | 毎日 |
| Flutter | FLUTTER | 10 | 過去7日 | 土曜のみ |
| セキュリティ | SECURITY | 3 | 過去48時間 | 毎日 |
| 暮らし欄 | CAREER | 1 | 直近1か月(なければ1年以内) | 毎日 |
| 今週のカレンダー | CALENDAR | 5件以内 | 今週(月曜〜日曜)の確定予定 | 月曜のみ |
| 名言 | 名言枠 | 1 | 歴史上の人物 | 毎日 |

「◯件以内」は上限で、無理に埋めない。質の良い候補が無いセクションは、見出しごと省略する。

## 区分ごとの選び方
- AIニュース: 生成AI、LLM、AI企業の動き、AIチップ、AIの社会的な影響。実務での使い方を扱うハウツー記事は「AI活用法」に回す。前日までの号と同じ話題は、大きな進展(新しい事実、数字、当事者の対応)がある場合だけ載せる。
- AI活用法: 生成AIやLLMを実際の開発・仕事に活用する方法論、ワークフロー、プロンプト設計、ツール活用のノウハウ。AI自体の発表ではなく、活用する側の実践知で、具体的な手順や学びのある記事を優先する。公開日または最終更新日が今日から1か月以内のものに限り、公開日が確認できない記事は載せない。
- ITニュース: AI、セキュリティ、Flutter/Dartを除く、IT業界・製品・サービス・インフラ・政策・ネット文化・ガジェット・企業の動向。注目されていれば、国内企業の提携・人事や、サービスの終了・障害も可。日本語の情報源から1件入れ、基本は3件を目指す。記事にFlutterとDartの情報は入れない。
- Flutter(土曜のみ): 過去1週間の主要な動きを、重要度の高い順に10件。FlutterとDartの記事は、このセクション以外には載せない(重大な破壊的変更は緊急枠に入れてよい)。
- セキュリティ: 脆弱性、攻撃事例、インシデント、対策。悪用が確認されているものと、モバイル・開発者に関わるものを優先する。AIとセキュリティにまたがる話題は、セキュリティに入れる。
- キャリア(暮らし欄): エンジニアのキャリア、働き方、学び方、転職、スキルの積み上げに関する良質な記事やブログ1件。
- 今週のカレンダー(月曜のみ): 今週にあるAI・IT・セキュリティ・Flutter/Dart分野の確定予定を日付順に。主要ベンダーの発表イベント、大型カンファレンス、月例パッチ配信日、Flutter/Dartの安定版リリース予定日などが対象で、公式発表で確認できるものだけを載せる。
- 名言: 歴史上の著名な人物の言葉を1つ。出典(著作、演説、書簡など)が確認できるものだけを選び、俗説的な名言は避ける。日本語訳を載せ、その直下に人物名(日本語表記)を大きく載せる。肩書き、生没年、出典(著作名や章など)と、人物の概要(2〜3文)を添える。分野(哲学者、科学者、政治家、作家、芸術家など)を順に回し、同じ人物が続かないようにする。
- 注目度で選ぶ: Hacker News(news.ycombinator.com。The Hacker Newsとは別物)と、はてなブックマークのホットエントリ(b.hatena.ne.jp/hotentry/it、AI関連は b.hatena.ne.jp/q/AI など)を必ず検索候補に入れ、ポイント数やブックマーク数が多い記事を優先する。取れた点数とコメント数(はてブは「◯ users」)は情報行にそのまま使い、リンク先はそれぞれのスレッドやブックマークページにする。各セクションの対象期間・除外ルールに合わない記事は載せない。
- 重複させない: セキュリティ、AIニュース、AI活用法、ITの順に先に選び、同じ話題は後のセクションから外す。

## 収集元サイト
記事は、原則として次のサイトから集める。一覧に載っていないサイトから採用するのは、一覧のサイトに候補が無いときだけにする。

| セクション | サイト名 |
|---|---|
| AIニュース | Hacker News、TechCrunch、The Verge、Ars Technica、ITmedia NEWS、各社の公式ブログ(OpenAI、Anthropic、Google、Meta、NVIDIAなど) |
| AI活用法 | Zenn、Qiita、note、はてなブックマーク(AI)、Hacker News、個人ブログ |
| ITニュース | はてなブックマーク(IT)、Hacker News、Publickey、ITmedia NEWS、GIGAZINE、各社の公式ブログ |
| Flutter | Flutter公式(docs.flutter.dev)、Dart公式(dart.dev)、pub.dev、GitHub Releases、r/FlutterDev、Zenn、Qiita |
| セキュリティ | JPCERT/CC、IPA、CISA、GitHub Security Advisories、BleepingComputer、The Hacker News(thehackernews.com)、各ベンダーの公式アドバイザリ |
| キャリア | Zenn、Qiita、note、はてなブックマーク、Hacker News、各社の技術ブログ |
| 今週のカレンダー | 各ベンダーの公式サイト、各カンファレンスの公式サイト |
| 名言 | 著作・演説・書簡など、出典が確認できる一次資料や信頼できる書誌情報 |

- Hacker News(news.ycombinator.com)とはてなブックマーク(b.hatena.ne.jp/hotentry/it、AI関連は b.hatena.ne.jp/q/AI)は、該当する全セクションで必ず見る。
- 記事には、どのサイトから採ったかを必ず記載する(手順3の「サイト名」)。

## 事前準備
- .claude/skills/make-newspaper/template.html を読む。
- docs/newspaper/archive/ の直近3号を読み、掲載済みの話題を把握する。

## 手順
1. セクションごとに別々にWeb検索して候補を集める。土曜以外はFlutterを検索しない。月曜だけ、今週のカレンダー用に公式発表予定・カンファレンス日程・リリース計画も検索する。
2. セクションごとに件数分を選ぶ。**本文を読めなかった記事(403、有料壁など)は載せない。** 本文を取得できる別の記事や別ソースを探す。
   - 面のセクション(AI・IT・Flutter・セキュリティ): 各セクションで最も重要な記事を1件だけ「トップ記事」にする(article に class="story top"、h3 に class="hd l")。他は article を class="story"、h3 を class="hd" にし、小さな話題は h3 に class="hd s" を付ける。AI面は、カテゴリ表示を記事ごとに AI / AI USE で使い分ける。
   - 暮らし欄: side-box。1件なのでトップ記事にせず、article は class="story"、h3 は class="hd"。
   - 今週のカレンダー: 暮らし欄と同じ side-box で、予定の件数分 article を並べる。meta のリンク文字は予定日(例: 9/29(月))、リンク先は公式発表ページ。見出しだけで分かる場合は本文を省いてよい。
3. 記事ごとに次を用意する。
   - サイト名(収集元サイトの一覧にある名称。記事を実際に見つけたサイトを書く)。情報行のリンク文字は「サイト名 · 経過時間, スコアp, コメント数 comments」(例: 「Hacker News · 2h, 669p, 412 comments」「ITmedia NEWS · 9/30」)の形にする。経過時間などが取得できない場合は、「サイト名 · 月/日」だけにして、リンク先は元記事にする。情報行は、カテゴリ(<span class="cat">)と、その横のリンクで作る。
   - 議論ページのURL(情報行のリンク先。なければ元記事URL)
   - 元記事のURL(見出しと「詳細を読む」のリンク先)
   - 1〜2文の「なぜ重要か」(要約ではなく、読者にとってなぜ重要かを書く。「何が起きたか」は見出しに任せ、影響・意味・背景を伝えて詳細を読みたくなるフックにする。固有名詞は<strong>、書名や機能名は<em>で囲む)
   - og:imageのURLが確認できた場合のみ画像を入れる。確認できなければ figure ごと省く。
4. 緊急枠: 悪用が確認された重大な脆弱性や、FlutterとDartの重大な破壊的変更など、今日中に知るべき事象がある日だけ入れる。
5. 名言を名言枠に入れる。

## 並び順
号外(緊急枠)を一番上に置く。本文は、AI、ITニュース、Flutter(土曜のみ)、セキュリティの順に面として並べる(第N面の番号は自動で付く)。その下に暮らし欄(月曜は今週のカレンダー欄と横に並べる)、さらにその下に名言を全幅で置く。暮らし欄だけの日(月曜以外)は、section に class="solo" を足して中央に寄せる。

## ルール
- template.html のCSSとクラス名は変えない。面の中身(記事)、下の欄(記事、名言)、号数、日付(年月、日、曜日)だけ差し替える。
- {波括弧}の部分を実際の内容で置き換え、テンプレート内の<!-- -->コメントは出力から全て削除する。記事ブロックは、テンプレートの例をコピーして件数分並べる。
- 出力しないセクション(号外、土曜以外のFlutter、月曜以外の今週のカレンダー、候補が無いセクション)は、見出しごと省く。名言のかぎ括弧はテンプレートが自動で付けるので書かない。
- URLは検索や取得で実際に確認できたものだけを使う。
- 記事の外部リンクは、すべて `target="_blank" rel="noopener noreferrer"` を付ける(テンプレートの例のとおり)。
- 元記事の文章をそのまま写さない。引用は15語未満にとどめ、それ以外は自分の言葉で書く。
- 号数は「2026年9月20日を第1号として、今日の日付までの経過日数+1」で計算する(例: 2026年9月21日は第2号)。
- 確認できない情報は載せない。憶測は書かない。件数が足りない場合は、載せられた分だけにして最後に不足を一行で報告する。

## 出力とpush
1. 完成したHTMLを docs/newspaper/archive/YYYY-MM-DD.html(日本時間の日付)として保存する。同じ日のファイルがすでにあれば、上書きする。
2. `python3 .claude/skills/make-newspaper/scripts/build_index.py` を実行して、docs/newspaper/index.html(バックナンバー一覧)を更新する。
3. `git push` ではなく、`mcp__github__push_files` ツールでリポジトリ `tttuuu1234/life` のmainブランチに直接pushする(owner: `tttuuu1234`, repo: `life`, branch: `main`)。`git push` はClaude GitHub Appの資格情報で認証され、contributions(草)に反映されないため。
   - files には、`docs/newspaper/archive/YYYY-MM-DD.html` と `docs/newspaper/index.html` の**2ファイルを、必ず1回の呼び出しでまとめて**渡す(別々に送ると、一覧が存在しない号を指す時間ができる)。内容は、保存したファイルをそのまま渡す。
   - message は「YYYY年MM月DD日 第X号 発刊」とする(例: 2026年09月21日 第2号 発刊)。
4. push前の2ファイルを別の場所に退避してから、`git fetch origin main && git reset --hard origin/main` でローカルをリモートに合わせる。`diff` で退避したファイルと一致することを確認し、一致しなければ差分を直して再pushする。
5. 最後に、その日のトップ記事の見出しと、セクションごとの掲載件数を数行で報告する。本文を読めずに載せなかった記事があれば、その旨も一行添える。
