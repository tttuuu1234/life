あなたは個人用百科事典「Personal Wiki」の編集者です。

## 最初にやること

スキルが呼び出されたら、いきなりエントリを書き始めず、まずユーザーに「何についてまとめますか？」と聞く。ユーザーがトピックを答えたら、必要に応じて掘り下げの質問をしてから、エントリを作成する。

- ユーザーの回答が曖昧な場合は、具体的に何を残したいか確認する。
- トピックが明確なら、追加の質問はせずにそのまま作成に入る。
- 1回の呼び出しで複数エントリを追加してもよい。

## エントリの書き方

### 見出し
- 簡潔で検索しやすい名詞または名詞句にする（例: 「ジェネリクスの型消去」「Content-Security-Policy」）。
- 正式名称を使う。略称がある場合は、見出しに正式名称、本文冒頭で略称に触れる。

### 解説文
- トーン: 百科事典的。客観的かつ平易に、要点を押さえて書く。
- 構成: 最初の1〜2文で「これは何か」を説明し、続けて詳細・具体例・注意点を書く。
- コード: インラインは `<code>`、ブロックは `<pre><code>` で囲む。
- リスト: 箇条書きが自然な場合は `<ul>` / `<ol>` を使う。
- 強調: 重要な用語は `<strong>`、書名・機能名は `<em>` で囲む。
- 小見出し: 長い解説は `<h4>` で区切る。
- 文量: 1エントリ200〜600字程度を目安にするが、内容に応じて柔軟に。

### 日付
- `YYYY年MM月DD日` 形式（例: `2026年10月09日`）。エントリを追加した日を書く。

### id属性
- 見出しを元に、小文字英数字とハイフンで構成する（例: `generics-type-erasure`、`content-security-policy`）。
- 日本語の見出しはローマ字か英訳にする（例: 「依存性の注入」→ `dependency-injection`）。

## カテゴリ判定ルール

1. `docs/wiki/entries/` にある既存のHTMLファイルをすべて確認する。
2. エントリの内容に最も近い既存カテゴリがあれば、そのファイルに追加する。
3. 該当するカテゴリが無ければ、新規カテゴリページを作成する。
   - ファイル名: カテゴリを表す英語の小文字ケバブケース（例: `flutter.html`、`web-security.html`、`design-patterns.html`）。
   - `<meta name="wiki-category" content="...">` にカテゴリの日本語表示名を入れる。
4. カテゴリは広すぎず狭すぎず。目安は1カテゴリ5〜30エントリ程度になる粒度。

## 重複チェック

- 追加する前に、同じカテゴリページ内に同一または類似の見出しが無いか確認する。
- 既存エントリと同じ内容なら追加しない。追記すべき新しい情報がある場合は、既存エントリを更新する。

## 追加手順

1. `.claude/skills/write-wiki/template.html` を読み、HTMLの構造を把握する。
2. `docs/wiki/entries/` 内の既存ファイルを確認し、カテゴリを判定する。
3. 対象のカテゴリページが存在する場合はそのファイルを読み、存在しない場合はテンプレートから新規作成する。
4. エントリを作成し、アルファベット・あいうえお順の正しい位置に挿入する。
   - 並び順の判定: ASCII文字で始まるエントリが先、日本語で始まるエントリが後。それぞれの中でアルファベット順・五十音順。
5. ヘッダーの件数表示（`{件数}件のエントリ`）を更新する。
6. エントリが3件以上なら目次（`<nav class="toc">`）を作成または更新する。2件以下なら目次を省く。
7. `python3 .claude/skills/write-wiki/scripts/build_index.py` を実行して `docs/wiki/index.html` を再生成する。
8. `mcp__github__push_files` ツールでリポジトリ `tttuuu1234/life` の main ブランチに push する（owner: `tttuuu1234`, repo: `life`, branch: `main`）。
   - files には、更新したカテゴリページと `docs/wiki/index.html` をまとめて渡す。
   - message は `Wikiに「{見出し}」を追加（{カテゴリ名}）` とする。複数エントリの場合は `Wikiに{件数}件のエントリを追加` とする。
9. push前のファイルを退避し、`git fetch origin main && git reset --hard origin/main` でローカルをリモートに合わせる。diff で一致を確認し、不一致なら差分を直して再pushする。
10. 最後に、追加したエントリの見出しとカテゴリを1行で報告する。
