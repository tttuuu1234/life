現在の変更を作業ブランチにコミット・pushし、`main` へのプルリクエストを作成する。

## 手順

1. macOSが自動生成するドットファイル（`.DS_Store`、`._*`、`.AppleDouble`）を `find . -name '.DS_Store' -o -name '._*' -o -name '.AppleDouble'` で探し、あれば `-delete` で消す。
2. `git status` と `git diff`（ステージ済み・未ステージ両方）で変更内容を把握する。コミット済みでpushしていない変更も含めて確認する（`git log origin/main..HEAD`）。
3. 変更もコミットもなければ「PRにする変更がありません」と伝えて終了する。
4. ブランチを確認する。
   - `main` にいる場合は、変更内容を表す作業ブランチ（例: `feature/session-auth`）を作って移る。セッションで指定された作業ブランチがあれば、そちらを使う。
   - 作業ブランチの以前のPRがマージ済みなら、`git fetch origin main` してから最新の `main` を元にブランチを作り直し、未マージの変更だけを載せる。マージ済みのPRを再利用しない。
5. 日本語のコミットメッセージでコミットする。
   - 1行目: 変更の要約
   - 必要なら2行目以降に補足
6. `git push -u origin <ブランチ名>` でpushする。
7. 同じブランチのオープンなPRがあるか `mcp__github__list_pull_requests`（owner: `tttuuu1234`, repo: `life`, head: `tttuuu1234:<ブランチ名>`）で確認する。
   - あれば新しく作らず、pushでそのPRが更新されたことを伝える。
   - なければ `mcp__github__create_pull_request` で作成する（base: `main`）。
8. PRのタイトルと本文は日本語で書く。
   - タイトル: コミットの1行目と同じ要約
   - 本文: 「概要」（何をなぜ変えたか）、「変更内容」（ファイルごとの箇条書き）、「確認したこと」（動かしたコマンドと結果。何も動かしていなければそう書く）
9. 作成したPRのURLをユーザーに伝える。

## ルール

- .env、credentials.json など秘密情報を含む可能性のあるファイルは除外し、警告する。
- 変更していないファイルは含めない。
- コミットメッセージやPR本文の確認はユーザーに求めず、そのまま作成する。
- マージはしない。マージはユーザーがGitHub上で行う。
- `main` に直接pushしたいときは、このスキルではなく `commit` スキルを使う。
