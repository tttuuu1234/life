# token-auth：トークン方式（JWT）の認証を体感する

Node.js 標準モジュールだけで書いた、最小のJWT認証サーバーです（`npm install` は不要）。
[session-auth](../session-auth/) と同じ題材（alice / bob、`/api/me`、`/admin`）で作ってあるので、見比べながら試すと違いがよく分かります。
モバイルアプリから叩くAPIを想定して、画面はなく、JSONだけを返します。学習用なので、本番では使わないでください。

## 起動

```bash
cd labs/token-auth
node server.js                     # http://localhost:3001（session-auth と同時に動かせるよう、ポートを分けている）
ACCESS_TTL_SEC=10 node server.js   # アクセストークンの寿命を10秒にして、期限切れを体感する
```

別ターミナルで、デモを流します。

```bash
bash demo.sh
```

ユーザーは session-auth と同じで、パスワードはどちらも `password` です。

| ユーザー | role |
|---|---|
| alice | user（一般） |
| bob | admin（管理者） |

## API

| パス | 内容 |
|---|---|
| `POST /login` | `{"username","password"}` を送ると、`accessToken`（JWT）と `refreshToken` が返る |
| `GET /api/me` | `Authorization: Bearer <accessToken>` で叩く。署名を検証して、トークンの中身を返す |
| `GET /admin` | 認可の例。トークンなしや改ざんなら **401**、一般ユーザーなら **403**、管理者なら 200 |
| `POST /refresh` | `{"refreshToken"}` を送ると、新しいトークン一式が返る（古いリフレッシュトークンは使えなくなる） |
| `POST /logout` | `{"refreshToken"}` を送ると、リフレッシュトークンを無効にする |
| `GET /debug/state` | サーバーが持っている状態を覗く（学習用） |

## demo.sh でやっていること

1. ログインして、トークンを受け取る
2. アクセストークンを「ヘッダー.ペイロード.署名」に分解して、中身を表示する。**暗号化されていないので誰でも読めます**
3. `Bearer` 付きで `/api/me` を叩く → 200
4. `Bearer` を付け忘れる → 401
5. alice で `/admin` → 403
6. ペイロードの `role` を `admin` に書き換えて送る → 署名が合わず 401
7. ログアウトする（リフレッシュトークンを無効化）
8. **ログアウトしたのに、同じアクセストークンで `/api/me` が 200 になる** ← JWTの弱点
9. 無効にしたリフレッシュトークンで再発行しようとする → 401
10. （寿命を30秒以下にして起動した場合）期限切れを待って `/api/me` → 401

## session-auth との違い

| | session-auth | token-auth |
|---|---|---|
| クライアントが持つもの | ただの番号札（`sid`） | 中身入りの通行証（JWT） |
| サーバーが持つもの | セッション表（`sid` → 誰か） | 署名用の秘密鍵だけ（＋リフレッシュトークンの表） |
| 「誰か」の判断方法 | 表を引く | 署名を検証して、中身を信じる |
| サーバー再起動 | 全員ログアウトする | 秘密鍵が同じなら、発行済みのトークンはそのまま使える |
| 即時ログアウト | 表から消せばすぐ効く | アクセストークンは期限まで使える。だから短命にする |

## やってみること

- `/debug/state` を開く。アクセストークンの記録がどこにもないことを確かめる
- サーバーを再起動しても、ログイン前に取ったアクセストークンで `/api/me` が通ることを確かめる（session-auth では追い出された）
- 発行されたトークンを [jwt.io](https://jwt.io) に貼って、中身を見る（本番のトークンは貼らないこと）
- `JWT_SECRET=other node server.js` で鍵を変えて起動し直すと、前のトークンが全部 401 になることを確かめる

## コードの読みどころ（server.js）

- `signJwt` / `verifyJwt`: JWTの作り方と確かめ方。ライブラリを使わずに書いているので、中で何をしているかが全部見えます
- `verifyJwt` の `alg` チェック: トークンが名乗る署名方式を信用しない。`alg: none` を通してしまう有名な脆弱性の対策です
- `issueAccessToken`: `sub`（誰か）、`role`、`iat`（発行時刻）、`exp`（期限）を入れています
- `refreshTokens`: リフレッシュトークンはJWTにせず、サーバーの表で管理しています。そのため、こちらは即時に無効化できます
